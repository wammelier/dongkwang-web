# E2E 테스트 (계획서 11장 핵심 4건)

실제 Supabase에 시험 전용 계정으로 접속해 브라우저로 확인한다. 브라우저는 PC에 설치된 **크롬**을 쓴다.

| 파일 | 확인하는 것 |
| --- | --- |
| `e2e/login.spec.ts` | 1. 로그인 — 비로그인 차단, 틀린 비밀번호 안내, 로그인 후 원래 화면, 로그아웃 후 다시 차단 |
| `e2e/content.spec.ts` | 2. 공지 작성 → 게시 → 방문자에게 공개 |
|  | 3. 임시 저장 글은 주소를 알아도 방문자에게 404 |
|  | 4. 주보 PDF 올려 게시 → 메인 ‘이번 주 주보’ 반영, 파일 열림 |

## 처음 한 번

```bash
npm run e2e:setup
```

- `e2e-editor@example.com` 시험 계정(콘텐츠 담당자)을 만들고 `.env.local`에 `E2E_EMAIL`·`E2E_PASSWORD`를 적는다.
- 비밀번호는 무작위로 만들고 화면에 출력하지 않는다. 다시 실행하면 비밀번호만 새로 바뀐다.
- 메일은 보내지 않는다(example.com, 확인 완료 상태로 생성).

## 실행

```bash
npm run e2e
```

- 개발 서버(`localhost:3000`)가 켜져 있으면 그대로 쓰고, 없으면 `npm run dev`로 띄운다.
- 시험 데이터는 제목에 `[E2E]`가 붙고, 끝나면 서버 키로 글·주보·올린 파일을 모두 지운다.
- 시험 계정이 없으면 계정이 필요한 테스트는 건너뛴다(비로그인 차단 1건만 실행).
- 실패하면 `test-results/`에 화면 기록(trace)이 남는다: `npx playwright show-trace <파일>`.

## 시험 계정 지우기

```bash
npm run e2e:remove
```

## 주의

- **운영 DB에 직접 쓰는 테스트**다. 실제 교회 데이터가 들어간 뒤에는 사람이 적은 시간에 돌리거나, 시험용 Supabase 프로젝트를 따로 두고 `.env.local`을 바꿔 실행한다.
- 4번은 2099-01-04 날짜 주보를 잠깐 게시한다. 테스트 도중에는 실제 메인에도 몇 초 보인다.

## 화면 녹화 영상 (둘러보기)

테스트와 별도로, 홈페이지 전체를 둘러보는 **영상**을 만든다. 자막과 마우스 표시가 들어가고 `e2e-videos/`에 저장된다. 내용과 안전장치는 [e2e-videos/README.md](../e2e-videos/README.md).

```bash
npm run e2e:login   # 어드민 영상용: 열린 크롬 창에서 사람이 직접 로그인 (비밀번호는 자동 입력하지 않음)
npm run e2e:video   # 웹사이트(PC·모바일) + 어드민 영상 촬영
```
