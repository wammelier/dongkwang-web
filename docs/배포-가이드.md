# 배포 가이드 (Vercel + Supabase)

`main` 브랜치에 올리면 Vercel이 자동으로 배포한다. **환경 변수를 넣고, 다시 배포(Redeploy)해야** 관리자 로그인과 실제 데이터가 동작한다.

## 지금 상태 (2026-11-10 점검)

`https://dongkwang-web.vercel.app` 배포는 성공했지만 **환경 변수가 하나도 없다.** 그래서:

| 증상 | 원인 |
| --- | --- |
| `/admin`이 "데이터베이스 연결이 필요합니다"로 나온다 → **관리자 로그인 불가** | Supabase 값 없음 |
| 공개 페이지가 실제 DB가 아니라 **예시 데이터**로 나온다 | 같은 이유 (설계된 대체 동작) |
| 사이트맵·robots·공유 이미지 주소가 `http://localhost:3000` | `NEXT_PUBLIC_SITE_URL` 없음 |

언제든 아래 명령으로 같은 점검을 할 수 있다. (읽기만 하고 아무것도 바꾸지 않는다.)

```bash
npm run check:deploy -- https://dongkwang-web.vercel.app
```

## 1단계. Vercel 환경 변수 4개

Vercel → 프로젝트 → **Settings → Environment Variables**

| 이름 | 값 | 주의 |
| --- | --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase 프로젝트 주소 `https://<프로젝트>.supabase.co` | 끝에 `/rest/v1/` 같은 경로를 붙이지 않는다 |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Supabase의 공개용(publishable) 키 | 공개되는 값이다 |
| `SUPABASE_SERVICE_ROLE_KEY` | Supabase의 **비밀(secret)** 키 | **서버 전용.** 이름 앞에 `NEXT_PUBLIC_`을 절대 붙이지 않는다. **Production에만** 넣고 **Sensitive**로 저장한다 (아래 참고) |
| `NEXT_PUBLIC_SITE_URL` | 이 사이트의 실제 주소 `https://dongkwang-web.vercel.app` | 도메인을 연결하면 새 주소로 바꾸고 다시 배포한다 |

- 값은 내 PC의 `.env.local`에 이미 있다. 거기서 복사하되 **`NEXT_PUBLIC_SITE_URL`은 `http://localhost:3000`이 아니라 위 주소로 바꿔서** 넣는다.
- 키 값을 채팅·메일·문서에 붙여 넣지 않는다. 이 저장소는 **공개**이므로 코드나 문서에 넣으면 안 된다.
- **Preview 환경에는 비밀 키를 넣지 않는다.** 미리보기 배포는 검토 전 코드를 실행하므로, 운영 비밀 키가 필요 없다. (미리보기 주소에는 Vercel 로그인 보호가 걸려 있다.)

### 환경 변수를 넣은 뒤: 반드시 다시 배포

`NEXT_PUBLIC_…` 값은 **빌드할 때 코드에 박힌다.** 변수만 바꾸고 그대로 두면 반영되지 않는다.

**Deployments → 가장 위 배포의 ⋯ → Redeploy** (*Use existing Build Cache*는 끈다)

## 2단계. Supabase 주소 설정

Supabase → **Authentication → URL Configuration**

- **Site URL**: `https://dongkwang-web.vercel.app` (도메인을 연결하면 그 주소)
- **Redirect URLs**: `https://dongkwang-web.vercel.app/admin/auth/**` 추가 (개발용 `http://localhost:3000/admin/auth/**`는 남겨 둔다)

이 설정이 없으면 **초대·비밀번호 찾기 메일의 링크**가 동작하지 않는다. (로그인 자체는 이 설정과 무관하다.)

## 3단계. 확인

1. `npm run check:deploy -- https://dongkwang-web.vercel.app` → 실패(✗)가 없어야 한다. 경고(!)의 "자리표시 문구"는 교회 정보를 채우면 사라진다.
2. `https://dongkwang-web.vercel.app/admin`에서 로그인되는지 확인한다.
3. 로그인 후 **대시보드 맨 아래 "서버 환경" 줄**을 본다 (최고 관리자에게만 보인다).
   - "알려진 보안 패치가 적용되어 있습니다" → 정상
   - "보안 패치가 필요합니다" → 서버의 Node.js가 수정 전 버전이다. 아래 "Node.js 보안 패치"를 따른다.

## Vercel 설정 확인 목록

| 위치 | 확인할 것 |
| --- | --- |
| Settings → General → **Node.js Version** | **26.x(최신 LTS, 새 프로젝트 기본값) 권장, 24.x도 가능.** 이 프로젝트는 `engines`가 `>=24`라 22.x 이하이면 설치가 막힌다 |
| Settings → Git → **Production Branch** | `main` |
| Settings → **Deployment Protection** | 미리보기 주소는 보호(로그인 필요), 운영 주소는 공개 — 지금 상태가 맞다 |
| Settings → Functions → **Function Region** | Supabase 프로젝트와 **같은 지역**이 빠르다 (Supabase가 서울이면 서울) |
| Settings → Environment Variables | 비밀 키는 **Production만**, **Sensitive** |

## Node.js 보안 패치 (Node2Shell, CVE-2026-111497)

2026-10-21에 Node.js의 압축(Brotli) 해제 취약점이 수정되었다. 수정된 버전은 **22.23.4 / 24.22.1 / 26.12.1 이상**이다.

- **Vercel**: 선택한 Node 줄의 패치 버전을 Vercel이 자동으로 올려 준다. 다만 **다시 배포해야 새 런타임이 반영**되고, 재배포 후에도 옛 버전이 보인다는 보고가 있어 **대시보드의 "서버 환경" 줄로 직접 확인**한다. 계속 수정 전이면 Vercel 공지(`vercel.com/kb/bulletin/node-js-security-advisory`)를 확인하고 지원에 문의한다.
- **이 PC(개발용)**: Node.js LTS 설치 파일로 덮어 설치하거나 `winget upgrade OpenJS.NodeJS.LTS`. 확인은 `npm run check:node`. 개발 서버를 켤 때(`npm run dev`)도 수정 전이면 경고가 나온다.
- 이 프로젝트 코드는 압축 해제를 직접 하지 않고 `brotli` 패키지도 쓰지 않는다. 다만 서버가 Supabase에서 받는 응답은 Node 내장 `fetch`가 풀기 때문에 **런타임 패치가 근본 해결**이다.

## 도메인 연결 (교회 명의로 구입한 뒤)

1. Vercel → Settings → **Domains** → 주소 추가 → Vercel이 알려 주는 DNS 값(A 또는 CNAME)을 도메인 업체에 입력
2. 연결되면 `NEXT_PUBLIC_SITE_URL`을 새 주소로 바꾸고 **Redeploy**
3. Supabase의 **Site URL / Redirect URLs**도 새 주소로 추가
4. `npm run check:deploy -- https://새-주소`

## 문제가 생기면

| 상황 | 해결 |
| --- | --- |
| 배포가 실패한다 | Deployments → 실패한 항목 → **Build Logs** 확인 |
| 변수를 넣었는데 그대로다 | **Redeploy** 했는지 확인 (빌드 캐시 끄고) |
| 관리자 로그인이 안 된다 | `check:deploy`의 "Supabase에 연결됨" 항목 확인, 변수 이름 철자 확인 |
| 메일 링크가 `localhost`로 간다 | `NEXT_PUBLIC_SITE_URL` 확인 후 Redeploy |
| 새 배포가 문제를 일으킨다 | Deployments에서 이전의 성공한 배포 ⋯ → **Promote to Production**(또는 Instant Rollback) |
| 파일 올리기가 막힌다 | 브라우저 콘솔의 "Content Security Policy" 오류 확인 → `NEXT_PUBLIC_SUPABASE_URL`이 설정·재배포됐는지 확인 |

## 계정·요금제

- Vercel, GitHub, Supabase 계정은 **교회 명의 이메일**로 두고 최고 관리자 2명 이상이 접근할 수 있게 한다.
- Vercel **Hobby** 요금제는 개인·비상업용 약관이 있다. 교회 사이트가 해당되는지 Vercel 약관을 확인한다.
- Supabase 요금제마다 **자동 백업 포함 여부**와 **오래 쓰지 않을 때의 일시 중지**가 다르다. 확인하고 백업 방식을 정한다.
